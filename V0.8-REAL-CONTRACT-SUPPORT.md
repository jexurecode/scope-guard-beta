# v0.8 — Real Contract Support (testing candidate)

Based on feedback from a real developer testing a roughly 50k-character agreement.

## What changed

1. Local PDF, DOCX and TXT import for original agreement and client request. Replaces editable textarea content after extraction, with warnings. Password-protected and image-only documents need separate preparation; no OCR is provided.
2. Longer agreements: max 150,000 characters (request: 20,000), while keeping v1 localStorage structure and compatibility with old analyses.
3. Explicit task splitting (numbered lists, bullet lists, semicolon/action-separated clauses) and preliminary results per task: likely covered / potential change / needs review. Agreement evidence is shown when a relevant clause can be found. Tasks after 24 are flagged for manual review instead of silently dropped.
4. 5-second sample panel on Dashboard that does not require creating a project.
5. V0.6/v0.7 analysis functionality remains, including mock-mode fallback and existing projects/history.

## QA runbook

```powershell
npm install
npm test
npm run build
npm run lint
npm run dev
```

First run **npm install** to generate `package-lock.json` (the stale original lockfile is omitted from this ZIP). Commit the generated lockfile afterwards. Full npm tests and production build were not run in the packaging environment because the npm registry and Linux native bindings were unavailable. Local TypeScript checks used temporary dependency stubs, not real PDF/DOCX package types.

Test manually in the browser:

- Import a real 50k-character TXT and DOCX agreement. Compare extracted text and length with the original.
- Import a real text-based PDF with multiple pages; check paragraphs, columns, tables, page warnings and whether it returns the expected terms. If any page is image-only, OCR before relying on analysis.
- Agreement: `Project includes two rounds of homepage copy edits and gallery image replacement. Customer booking systems are excluded.`
- Request: `1. Update homepage copy. 2. Replace gallery images. 3. Add a customer booking system.` (prefer separate numbered lines).
- Expect 2 likely-covered and 1 potential-change task, including agreement evidence for the excluded booking request.
- Test a real ambiguous contract, negative wording and removed features. Reject false certainty.
- Confirm an existing v0.6 workspace loads unchanged. Save/reopen analysis and edit client reply.
- Confirm offline document parsing (with dependencies preloaded), no AI network traffic, and that data does not leave the browser.

## Explicit limitations

- This release **does not** incorporate real AI. The rules cannot reliably judge arbitrary or ambiguous legal scope. No guarantee of correctness.
- No OCR, password-protected files, `.doc`, scanned image extraction, or cross-device sync. File bytes never go to an API, but extracted text is saved to browser localStorage.
- Full text and history snapshots consume localStorage quota; saving may fail. The app will warn and keep the in-memory workspace, but the user must keep independent backups.
- No clause/page-level citation alignment beyond best-matching quoted snippets; long contracts must still be human-reviewed. Some clauses with nested lists or unusual formatting will not parse perfectly.
- Public beta remains unchanged until local build, test and browser checks pass.
