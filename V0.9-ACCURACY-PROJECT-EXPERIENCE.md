# Scope Guard v0.9 — Accuracy & Project Experience

## Implemented

- Explicit agreement exclusions can be matched outside the built-in catalog. Short exclusions, plural words, noun lists, contractions and basic exclusion headings are supported. Matching requires the meaningful words of a bounded subject to appear in the request; incidental overlap with one word of a multiword subject is insufficient.
- Blog and article-page capabilities have explicit catalog aliases. Blog links, quoted examples, conditional requests and modifications retain conservative handling.
- Agreement clauses that include and exclude the same capability require review. Optional and qualified wording is kept separate from definite inclusion or exclusion.
- Exclusion evidence is retained in task assessments and potential-change results, displayed alongside the request, and preserved in saved history. Replies identify the requested deliverable, including unknown capabilities.
- New Project has a dedicated view. Successful creation opens the selected project's workspace directly.
- Project workspaces contain that project's agreement and analysis/request history, with an action to start a fresh request. Reopening an analysis continues to show its saved agreement snapshot.
- Cards use previews limited to 175 characters. View Full Agreement opens a scrollable, whitespace-preserving view. The original agreement is never truncated in storage or analysis.
- Duplicate names are detected after trimming and case normalization. Creation offers either a fresh request on the existing project or explicitly creating a separate engagement. Rename refuses accidental collisions. Existing duplicate records remain intact.
- Project search opens the project's workspace. Desktop and mobile navigation retain project highlighting for the new views.
- Rule-based and hybrid mock modes remain local simulations; no AI provider or API keys were added.

## Data compatibility

The localStorage key `scope-guard-workspace-v1`, workspace version 1, project IDs, full agreements and historical inputs remain unchanged. `agreementEvidence` on detected changes is optional so older snapshots remain readable. No migration or automatic merging/deletion runs. Existing storage-failure recovery remains in place.

Browser storage belongs to the browser profile and origin (scheme, hostname and port). A separate localhost origin will not show the live beta's saved records. Do not clear existing browser storage while validating preservation.

## Windows validation still required

Extract this ZIP into a fresh folder. Use Node 24, open PowerShell in `scope-guard`, then run:

```powershell
npm ci
npm test
npm run build
npm run lint
npm run dev
```

Manual browser checklist:

1. Open the app in desktop and narrow mobile layouts; confirm light remains the default on a fresh profile and the manual theme switch works.
2. Create a project from New Project. Confirm it opens its workspace, import an actual PDF/DOCX/TXT agreement, and verify the entire text including its final paragraph.
3. Analyze `Please add a blog with a page for each article.` against `Build a landing page. Blog is not included.` Confirm a potential change, exclusion evidence and a blog-specific editable reply.
4. Use a real long contract with two covered tasks and one excluded task. Review each task and its evidence; do not assume keyword matching establishes contractual coverage.
5. Save requests in two projects. Open each workspace and verify only that project's history is shown. Reopen history, edit a reply, and start a new request; confirm snapshots remain unchanged.
6. Enter the same project name with different capitalization. Test both duplicate choices. Confirm a separate engagement is created only after explicitly choosing it; no project is merged.
7. Inspect long-agreement cards and View Full Agreement. Check scrolling and mobile wrapping. Reload on the same origin and confirm the complete agreement, projects and history are retained.
8. Confirm importing files and opening projects do not mix another project's inputs. Verify no unexpected console errors, including PDF worker failures.

## Limits and deployment

This remains a bounded English rule-based engine, not semantic AI or a contract interpreter. Complex references, synonyms, nested conditions and unusual agreement layouts can still require manual review. Agreement evidence snippets are bounded to 350 characters; full agreements remain stored intact. The existing 24-task assessment limit remains visible when exceeded.

No production deployment was performed. Validate the browser checklist before considering deployment; production deployment requires approval.
