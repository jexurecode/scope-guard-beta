# Scope Guard v0.8 — regression fix 2 (testing candidate)

This source ZIP follows the reported Windows run of **256 passed / 4 failed (260 tests)**.

## Corrected behavior

- The task splitter now keeps quoted examples intact, so `The client said "add payments and add booking and add login"` is not turned into three unconditional tasks.
- Conditional prefixes such as `When we launch,` and `If we expand,` stay attached to their actions. Independent tasks after a period, newline or semicolon still split.
- Leading uncertainty (`Maybe ...`) applies across same-sentence `and add` clauses. It does not suppress a definite request in a later sentence.
- Multi-task client replies explicitly name detected capabilities (e.g. `booking system`) instead of relying on the raw request using that exact word. They no longer copy a long fragment containing unrelated exclusions into the reply.
- Added 8 focused regression tests in `src/lib/v08-regression.test.ts`; existing assertions are unchanged.

## Checks completed in this environment

- **197 passing / 0 failing** focused Node assertions, compiled from the actual source and eight test files with a lightweight assertion harness. This is **not** a Vitest run and is not a substitute for it.
- TypeScript 5.8 `tsc -b` completed with temporary ambient declarations for unavailable PDF/DOCX packages. The temporary declarations are **not included** in the ZIP. Windows with installed dependencies must perform the authoritative type check.
- ZIP integrity verified.

## Not verified here

- Full native Vitest run, actual PDF/DOCX import, Vite production build, and oxlint. The package registry is inaccessible in this environment and the previously uploaded Windows `node_modules` cannot run the Linux native bundler.
- The original `package-lock.json` did not include `mammoth` or `pdfjs-dist`, so it is **omitted** from this ZIP. Run `npm install` (not `npm ci`) to generate a fresh lockfile, then commit it.
